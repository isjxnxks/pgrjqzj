## 3. 取证方法

### 3.1 收集品（B）
1. 从 APK 解出原始 dump，按**长度前缀**切分字符串（`脚本_长度前缀重解.py`）；标题在 `du3.bin` 里 `find()` 定位，从该偏移起截块（`脚本_收集品_抽取7.py`）。
2. 游戏用**字面 `\n`** 作换行标记 → 渲染时还原真换行。
3. 43 条各带一个 10 位十六进制 `fp`，实测**互不重复**（生成脚本未随包保存，算法未知，见 [`06_收集品.md`](06_收集品.md) §1.3）→ 可作"未串条"的旁证。
4. `02_收集品解包/_说明.md` 记：43 条字段与游戏内截图**抽比 15 条，0 处不符**。本套资料按此登记，**未逐条复核到 43**——第一部分的 `time`/`keeper`/`lv` 尤其只有脚本启发式，`KNOWN` 自检表只覆盖 #25–#43。
5. 已知残留异常：#33 正文有 14 个字面 `\n` 却有 15 个真实换行（`鸠：……` 后多一个裸 LF）——属原始数据实况，不修正。
6. ⚠️ 切分口径本身是可查的：`重解.py` 的 `if len(t) < 4: continue` 与 `lang_of()` 的单字符判定规则直接造成了 #43 的两条脏正文，见 [`06_收集品.md`](06_收集品.md) §8.3。

### 3.2 倒计时页（A/B）
- 同一 URL 连抓三份 HTML（16:12 CST），**逐字节 diff** → 三份仅 Cloudflare `r`/`t` 参数不同（`t` 为 base64 epoch 秒），正文相同。
- `monitor.jsonl` 以 ~61 s 间隔轮询并记 `rawHash`/`normHash`/`changed` → 证明"看着在变"只是挑战参数轮换。
- `分析2_写入与画布.log` 记录单次时刻的 DOM 属性写入与 canvas 绘制拦截 → 定位 `inline_2` 只建了 1×1 隐藏 iframe，且未画任何文字。
- **PNG 尾部拼接**：解析 chunk 至 `IEND`，切出尾部 → `start_后半段.bin` 与 `start_后半段.png` 字节相同且是合法 PNG（1920×1080）。**"图中藏图"由文件结构证明，不靠像素肉眼判读。**
- `反混淆_回填版.js`：把 445 处解码器调用回填成明文字符串，从而能读出 canvas id、字符集、颜色、`IEND`、fetch URL 等常量。

### 3.3 截图（B）
只在**核对字段**时开图（定数、曲师、地图节点、曲绘、版本号、收集品页头部三字段）。不做"逐张描述"——那既浪费又易生编造。
图上的小字（地图节点标签、曲绘背景警示牌）在 2000×1200 原图里读不清时，用 PIL **裁区＋LANCZOS 放大**后再读，不要凭印象猜。本套资料里三处结论就是这么来的：地图标签实为 **`Project PhigrOS`**（大写 O，不是 `Phigros`）、四张终曲曲绘是**同一座月台的连续镜头**、地图顶部大菱形是 **thtw (Rework) 曲绘**而非「答案」节点。
> ⚠️ **放大倍率会直接改变结论。** 3× 下 `Camellia` 被读成 `Camelila`（少一个 l），6× 才确认；同一批节点缩略图在 3×/4× 下曾被写成"月台相拥图"，6× 才看出是另外两幅画。**读小字一律用 ≥5×，且标签与画面要分别确认。**

### 3.4 过程记录（方法证据）
`07_过程记录` 用于回答"这条结论怎么来的"。检索方式：`grep -n -m N -C 3`，不整篇读。
**覆盖边界（重要）**：该导出止于 **2026-10-02 15:57**，即第二部分上线前约 1 小时。因此**噪域、13 节点地图、#25 及其掉落率、第二部分 19 条、未知信号说话人**等内容**都不在其中**——不要以为"日志里没有 = 结论无据"，它们来自 10-02 之后的另一轮实测与解包。
